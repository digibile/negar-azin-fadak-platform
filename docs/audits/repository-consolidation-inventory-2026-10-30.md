## فناوری واقعی مخزن مقصد
- Root package manager: pnpm 12.3.4
- Web: Next.js 16.3.4، React 19.1.0، TypeScript
- API: TypeScript، Express 5، PostgreSQL driver، Zod
- Database: PostgreSQL و migrationهای SQL نسخه‌گذاری‌شده
- Deployment: Docker Compose و GitHub Actions

## تعارض‌ها و ریسک‌های کشف‌شده
1. کتاب معماری مخزن اصلی دامنه تجاری `sookar.com` و مسیر استقرار `/home/sookar/domains/sookar.com/negar-platform` را ذکر می‌کند؛ تصمیم فعلی مالک برای انتشار `sookar.ir` است. این دو نباید بدون تصمیم صریح با هم جایگزین شوند.
2. مخزن اصلی TypeScript/Express است، در حالی که مخزن مادر جدید ASP.NET Core 10 است. این دو دارای مرزهای دامنه و مدل‌های مشابه‌اند؛ ادغام فایل‌به‌فایل باعث دو هسته اجرایی و دو منبع حقیقت می‌شود.
3. مستندات MASTER-MOTHER درباره فناوری فرانت‌اند یکدست نیستند: README/AGENTS به Next.js اشاره می‌کنند، اما `frontend/package.json` از Vite استفاده می‌کند. باید با فایل‌های اجرایی تطبیق داده شود.
4. README مخزن Vamcity حذف فایل‌های tracked از main را اعلام می‌کند، اما درخت فایل‌ها هنوز 66 فایل شامل workflowها و کدهای محدود را نشان می‌دهد؛ وضعیت تاریخچه و branchها باید بررسی شود.
5. مخزن حسابداری فقط ZIP دارد و تا استخراج آن نمی‌توان درباره زبان، ساختار یا قابلیت‌ها نظر قطعی داد.
6. مخازن Sarajon و Vamcity احتمالاً فایل‌ها و مدل‌های مشترک دارند؛ انتقال هر دو بدون diff موجب تکثیر کد می‌شود.
7. هر مخزن private باید از نظر مجوز خواندن/انتقال و هر گونه فایل محرمانه، مجوز جداگانه بررسی شود.

## سیاست ادغام
- هیچ مخزن منبعی حذف، آرشیو یا بازنویسی نمی‌شود.
- تاریخچه و شناسه منبع هر بخش منتقل‌شده باید قابل ردیابی بماند.
- فایل‌های secrets، env واقعی، کلیدها، بکاپ‌های حاوی داده شخصی و اطلاعات بانکی وارد Git نمی‌شوند.
- ابتدا مقایسه domain/API/schema و تست؛ سپس انتقال انتخابی در شاخه ادغام.
- دیتابیس تولیدی و سرویس‌های فعلی دست‌نخورده می‌مانند تا برنامه مهاجرت، backup/restore و آزمون پذیرش تأیید شود.
- انتشار فقط پس از build، تست، بررسی migration و تأیید SHA دقیق انجام می‌شود.

## کارهای بعدی

## بررسی تکمیلی استقرار Sookar
فایل `.github/workflows/deploy-sookar-main.yml` در مخزن اصلی بررسی شد:
- workflow دارای ورودی دستی `workflow_dispatch` است.
- استقرار روی سرور فقط با ورودی صریح `deploy_to_server=true` یا شرط مشخص commit انجام می‌شود؛ Push عادی به‌تنهایی نباید سرور را تغییر دهد.
- preflight صریحاً دامنه `sookar.ir`، مسیر `/home/sookar/domains/sookar.ir/negar-platform`، فایل محیطی موجود با مجوز 600، بلوک Nginx و گواهی TLS را بررسی می‌کند.
- بنابراین workflow فعلی برای `sookar.ir` تنظیم شده است؛ اشاره `sookar.com` در کتاب معماری، مستند قدیمی/متناقض است و باید در تغییر جداگانه مستندات اصلاح شود.
- این بررسی صرفاً خواندن workflow است؛ workflow اجرا نشده و استقرار انجام نشده است.


## بررسی هم‌پوشانی کد و قابلیت‌های موجود
مقایسه SHA فایل‌ها در درخت‌های Git نشان داد:
- `vamcity` و `digibail`: حداقل 35 فایل با مسیر و محتوای دقیقاً یکسان.
- `vamcity` و `sarajon`: حداقل 37 فایل با مسیر و محتوای دقیقاً یکسان.
- `digibail` و `sarajon`: حداقل 32 فایل با مسیر و محتوای دقیقاً یکسان.

بنابراین این سه مخزن سه محصول کاملاً مستقل نیستند؛ بخش قابل توجهی از Core، Security، Tenancy، Operations، Preview و نصب آن‌ها مشترک است. ادغام هر سه به‌صورت کپی کامل باعث تکثیر قطعی کد می‌شود. منبع canonical هر قابلیت باید با بررسی آخرین commit، نسخه اجرایی و تست انتخاب شود.

همچنین مخزن اصلی هم‌اکنون فایل‌ها و مسیرهای اجرایی مرتبط با `lendtech`، `accounting`، `finance`، `domain-marketplace`، `installments`، قراردادها، تسویه، فروشنده، سفارش و واردات/تجارت دارد. بنابراین انتقال این حوزه‌ها باید ابتدا به‌صورت مقایسه و تکمیل قابلیت انجام شود، نه افزودن ماژول موازی.

## اولویت پیشنهادی انتقال
1. `MASTER-MOTHER-NEGARAZINFAKA`: ممیزی عمیق معماری، هویت مرکزی، Tenant isolation، مستندات و تست‌ها؛ سپس تصمیم درباره استخراج قابلیت‌های فاقد معادل. این مخزن یک پیاده‌سازی مستقل ASP.NET Core 10 است و نباید بدون تصمیم معماری به‌عنوان backend دوم در کنار API اصلی فعال شود.
2. `negarazin-accounting`: استخراج ZIP و فهرست‌برداری کامل از کد، schema، گزارش‌ها و منطق حسابداری؛ مقایسه با حسابداری فعلی قبل از انتقال.
3. `digibail` / `vamcity` / `sarajon`: انتخاب یک baseline بر اساس کامل‌ترین نسخه و تاریخچه؛ انتقال فقط قابلیت‌های متمایز مانند قراردادها، تعریف وام، درخواست وام، اسناد، OTP، پیامک و گردش‌کار مهاجرت داده.
4. `tejarhstore`: استخراج دامنه فروشگاهی و تطبیق Product/Category/Cart/Order/Brand با بازارگاه موجود.
5. `uminex` / `sitnela` / `aqayevam`: فعلاً هیچ کد اجرایی قابل انتقالی در main مشاهده نشد؛ تا دریافت branch یا فایل دیگر، وارد فاز ادغام نمی‌شوند.
